# 开发运营流程（从选题到复盘，一款游戏走一遍）

目标：**一款游戏从选题到上线不超过 2 周**，流程固定、每步有产出物，不靠临场发挥。

## 流程图

```
选题调研（0.5 天）→ 复制模板换皮（3–5 天）→ 本地自测（0.5 天）
  → 上线（0.5 天）→ 分发（1–2 天）→ 7 天数据复盘 → 决策：迭代 / 复制 / 停掉
```

## 每步产出物

| 步骤 | 产出物 | 验收 |
|---|---|---|
| 选题调研 | `docs/topic-research.md` 表格填完 + 1 个结论 | 3 条筛选标准全满足 |
| 复制模板换皮 | `games/<slug>/` 四个文件 + `assets/` + `README.md` + `VERSION` | 模板 README 的换皮 5 步走完 |
| 本地自测 | `release-checklist.md`“上线前”全勾 | 桌面+手机各 3 局，无报错 |
| 上线 | 线上 URL + `CHANGELOG.md` 一行 | “上线当天”全勾，GA4 实时见 `game_start` |
| 分发 | itch/CrazyGames 上架 + 1 条 15 秒短视频 | 外链打开就是游戏页 |
| 7 天复盘 | `games/<slug>/README.md` 结论：迭代 / 复制 / 停掉 | 三个结论只选一个 |

## 分发清单（上线后 1–2 天内）

按顺序做，做完一个勾一个：

1. itch.io：新建项目 → 上传游戏文件夹 zip → 勾“Play in browser” → 免费发布
2. CrazyGames / GameDistribution：按平台表单提交（要审核，等结果，不催）
3. 主站入口（已走方案 B 时）：首页或相关页加 1 处游戏入口链接
4. 短视频 1 条：录 15–30 秒实机玩法（得分/失败名场面），发 TikTok / YouTube Shorts，标题带玩法+生肖
5. Poki：放最后——审核最严，等前两个平台有数据再投

不要做的：上线第一天就全平台群发、买量、同时开两个游戏——先让 1 个跑出数据。

## 运营节奏（每款游戏）

- 第 1 周：每天看 GA4 实时 + 本地 fallback，修致命 Bug（打不开、分数不动、手机点不了）
- 第 2 周：只改 1 个点（最痛的那个：太难就降速、没人分享就改分享文案），改完 bump 小版本重新上线
- 第 3 周起：不动它了，看 7 天复盘结论；要迭代就排进下一轮，不要无限改同一款

## 换皮复制（数据好的游戏才复制）

- 复制的是 `games/<好游戏>/`，不是 `template/`——玩法已验证过，只换题材/贴图/数值
- 复制后必改：`slug`（新文件夹名）、`title`、贴图、`config.js` 难度数值；`VERSION` 从 `0.1.0` 重新开始
- 复制品也要单独走一遍 `release-checklist.md`，不能因为“玩法一样”就跳过测试

## 版本与分支（轻量，不搞复杂 Git Flow）

- `main` 分支就是线上；开发在 `games/<slug>/` 里直接改，改完自测、上线
- 每个游戏一个文件夹，互不干扰；不要跨游戏共用一份 `main.js`（复制时各自改，改崩一个不影响另一个）
- 每次上线记 `CHANGELOG.md`：版本、日期、改了什么、数据结论
